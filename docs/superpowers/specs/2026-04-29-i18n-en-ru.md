# i18n (English / Russian) — v1.1 Design

Date: 2026-04-29
Status: agreed during brainstorming

## Goal

Make English the primary site language and add Russian as a secondary
locale. Locale is auto-detected from the browser, defaults to English,
and can be overridden by the user via a small switch in the header.
The choice persists in `localStorage`.

This is an additive iteration on top of v1: behaviour and architecture
of the decoder do not change. Only the way text is sourced does.

## Scope

### In scope

- All user-facing text in `index.html` becomes locale-driven.
- All user-facing text in `src/app.js` (button labels, placeholder,
  collapsed-input header, summary parts, copy/edit feedback, alert) becomes
  locale-driven.
- Decoder error messages: `DecodeError` carries an error **code** instead
  of a Russian string. UI maps the code to the localised message.
- A `EN · RU` switch in the page header that flips the locale and
  persists the choice.
- `README.md` rewritten in English.
- Russian comments inside source files (`src/decode.js`, `src/app.js`)
  rewritten in English.
- Future specs and plans are written in English.

### Not in scope

- Existing v1 spec/plan in `docs/superpowers/` stay in Russian as
  historical artefacts. We do not retro-translate them.
- A third locale. Architecture should not block adding one, but we are
  not going to build for it now.
- Any change to decoder behaviour, fixtures, or tests beyond the error-code
  refactor.

## Architectural decisions

- **One file, one dictionary.** `src/i18n.js` exports `t(key)`,
  `setLocale(loc)`, `getLocale()`, and an internal `messages` object
  with `en` and `ru` blocks. No external library, no JSON fetching, no
  build step.
- **Decoder stays language-neutral.** `DecodeError` no longer carries
  a Russian string. It carries an error **code** (a string constant such
  as `"BAD_BASE64"`) plus an optional default English message. The UI
  translates the code via `t('errors.' + code)`.
- **Locale resolution order:**
  1. `localStorage.getItem('locale')` if it is `'en'` or `'ru'`.
  2. `navigator.language` parsed to a 2-letter primary tag. If it equals
     `'ru'`, use Russian. Otherwise English.
- **Switch is part of the page shell**, not the dynamic `#app` content,
  so it is always visible regardless of decoder state.
- **Single source of truth for the locale.** When the user clicks the
  switch, we call `setLocale(loc)`, which writes to `localStorage`,
  updates `<html lang>`, and triggers an app re-render.

## Files

- **Create** `src/i18n.js` — dictionary + `t / setLocale / getLocale`
  helpers. Roughly:

  ```js
  const messages = {
    en: { /* ~30 keys */ },
    ru: { /* ~30 keys */ }
  }

  let current = 'en'

  export function getLocale() { return current }

  export function setLocale(loc) {
    if (loc !== 'en' && loc !== 'ru') return
    current = loc
    try { localStorage.setItem('locale', loc) } catch {}
    document.documentElement.lang = loc
  }

  export function detectLocale() {
    try {
      const stored = localStorage.getItem('locale')
      if (stored === 'en' || stored === 'ru') return stored
    } catch {}
    const nav = (navigator.language || 'en').slice(0, 2).toLowerCase()
    return nav === 'ru' ? 'ru' : 'en'
  }

  export function t(key) {
    const dict = messages[current] ?? messages.en
    return dict[key] ?? messages.en[key] ?? key
  }
  ```

  Keys are flat dotted strings: `header.title`, `buttons.decode`,
  `errors.BAD_BASE64`, etc. Flat keys keep the dictionary trivially
  serialisable and easy to grep.

- **Modify** `src/decode.js`
  - Add error-code constants (e.g. `EMPTY_INPUT`, `BAD_PREFIX`,
    `BAD_BASE64`, `BAD_ZLIB`, `BAD_JSON`, `INTERNAL_NO_INFLATE`,
    `WRONG_INPUT_TYPE`).
  - `DecodeError` now takes `(code)` and exposes `error.code` plus an
    English default `error.message`. No Russian strings remain in the
    file.
  - Existing tests update to assert on `error.code` rather than the
    Russian regex match.

- **Modify** `src/app.js`
  - Import `t / setLocale / getLocale / detectLocale` from `./i18n.js`.
  - On startup: `setLocale(detectLocale())` before the first `render()`.
  - Replace every Russian inline string with `t('...')`.
  - Map `DecodeError.code` to a localised string via
    `t('errors.' + e.code)`. For other errors, fall back to
    `` `${t('errors.UNKNOWN')}: ${e.message}` ``.
  - Re-translate inline comments to English.

- **Modify** `index.html`
  - `<html lang="en">` (the runtime updates it on locale change).
  - Header gets a small `<div class="locale-switch">EN · RU</div>` next
    to the title; clicking either tag flips locale.
  - Static page text (header title, subtitle, footer) is set once on
    startup by `app.js` reading `t(...)` rather than baked into the
    HTML — keeps a single source of truth.

- **Modify** `styles.css` — minimal: `.locale-switch` styling, two states
  for active/inactive.

- **Modify** `README.md` — full English rewrite. Same structure as the
  current Russian-flavoured one (purpose, local development, layout,
  out of scope), but in English.

## Locale switch UX

Tiny tagline in the top-right of the header:

```
EN · RU
```

- The active tag is bold/blue, the other is grey.
- Click the inactive one → `setLocale(other)`, re-render whole page.
- Switching locale on the decoded view preserves all state (input,
  result, selected path, current view) — only labels change.

## Tests

- `decode.test.js` updates: every `toThrow(/русский регексп/)` becomes
  `expect(() => decode(...)).toThrow(DecodeError)` plus a follow-up
  `expect(error.code).toBe('XYZ')` check. Use `expect(...).rejects.toMatchObject({ code: ... })`
  pattern, or wrap in `try / catch`. Pick the cleaner form during
  implementation.
- `i18n.js` does not need its own test file: it is small, pure, and its
  output is verified end-to-end through `decode.test.js` (codes only,
  no UI text) and manual UI sweep.
- Manual UI sweep: load the page in `en` (default), confirm all text
  is English. Click `RU`, confirm everything flips and the JSON pane
  is unaffected. Reload — the choice is remembered. Open in a fresh
  browser with Russian system locale — should auto-pick Russian. Open
  in English browser — should auto-pick English. Trigger every error
  case (wrong prefix, corrupt base64, broken zlib, broken JSON) in both
  locales, confirm message is correct.

## Compatibility / migration

- **Tests** referencing Russian error text break — they get rewritten
  in the same change.
- **Existing fixtures** are language-agnostic; no change.
- **Existing GitHub Pages deployment** keeps working: this is a single
  push, no infrastructure change.
- **Live users** (basically only the author at this point) will see
  English on first reload after the change unless their browser is
  Russian. If they liked the Russian version, one click on `RU`
  preserves it forever.

## Out of scope (explicitly)

- Translating the existing v1 spec / plan / brainstorm artefacts.
- Adding additional locales.
- Server-side language negotiation (we do not have a server).
- Locale-aware number/date formatting (we don't display either).
